# P NewTone ～響け、最後の一音～

大学アカペラサークル「NewTone」を題材にした、液晶演出中心の身内向けWebパチンコゲーム第1版です。金銭を賭ける機能と玉の描画・物理演算はありません。

## 起動・確認

Node.js 24以降を用意し、次を実行します。テストにはNode.jsのTypeScript型除去機能を使用します。

~~~sh
npm install
npm run dev
~~~

表示されたローカルURLを開き、液晶をクリックまたはタップしてください。品質確認は次のコマンドです。

~~~sh
npm test
npm run build
npm run preview
~~~

## 技術構成とファイル構成

Vite、TypeScript、HTML、CSSのみを使用しています。ReactやCanvasは導入していません。抽選、状態遷移、保留キューをUIから分け、画面演出はTypeScriptの進行とCSS animationで動かします。

- src/game/probability.ts — 確率、ST境界、保留色ごとの条件付き確率
- src/game/holds.ts — 最大4個のマイク保留、追加・消費・色指定
- src/game/spinResult.ts — 変動開始時の当落、図柄、RUSH突入の決定
- src/game/engine.ts — NORMAL、JACKPOT、RUSH3区間、行事ステージの進行と保留の自動消化
- src/presentation/plan.ts — 決定済みの当落に合う結果発表・アカスピ・復活演出とステージ移行の選択
- src/presentation/campusAudition.ts — 学内オーディションの点数・順位・通過結果の生成
- src/presentation/runner.ts — 行事別の変動、結果発表、アカスピ、ステージ移行、RUSH、BONUSの画面進行
- src/presentation/ui.ts、audio.ts、style.css — 液晶表示、仮SE、実機風CSS
- src/data/ — 年間行事とステージ移行条件、アカスピ4段階、内ステ曲数、差し替え素材の一覧
- tests/ — 確率、保留の自動消化、ST区間、出玉、リーチ図柄の検証

画像は public/assets/ に配置し、src/data/assets.ts のパスを設定すると数字図柄やSEを差し替えられます。素材未設定時はCSS図柄とWeb Audioの簡易SEを使用します。行事や身内ネタは src/data/ のデータを増やし、必要なら plan.ts に選択条件、runner.ts に演出タイプの画面進行を追加してください。第三者の画像・楽曲は同梱していません。

## スペック

- 通常時大当たり：1/319.7。初当たりは1500発、60%でRUSH突入、40%で通常時へ戻ります。
- RUSH：ST120回転。全区間で大当たり確率は1/73、120回以内の継続率は約81%です。RUSH中の大当たりは1500発、ST120回を再セットします。
- ST 1～30回は高速ゾーン、31～100回は先読み・リーチ中心のメイン、101～120回はアンコールのラストゾーンです。120回転目には専用の最終変動を表示します。

マイク色は白 ＜ 青 ＜ 緑 ＜ 赤 ＜ 金 ＜ 虹の順です。入賞時に色を選び、変動開始時に色に応じた当たり確率で抽選します。色の出現率と条件付き確率の重み付き平均が通常時1/319.7、RUSH中1/73と一致します。虹は大当たり確定です。デバッグの強制指定はこの通常抽選を上書きします。

## 入賞・保留・演出

液晶のメイン領域を1回タップまたはクリックすると、スタートチャッカーへ1玉入賞した扱いでマイク保留を1個追加します。玉は表示しません。変動中にも最大4個まで貯められ、保留があれば変動終了後に次を自動消化します。液晶下端にも「消化中」と「待機保留」を表示し、入賞が変動開始に使われたか待機中か分かるようにしています。満タン時は追加されず「保留MAX」を表示します。

任意のHANDLEをONにすると約1.25秒ごとに自動入賞します。OFFにすると新規入賞が止まり、貯まっている保留は引き続き自動消化されます。タップ入賞はHANDLEの状態に関係なく使用できます。PUSHは演出の指示が出た時に押せます。押さなくても一定時間後に進行します。

通常時は数字1～7の3図柄、内ステ通過バンド数予告、学内オーディションの採点、アカスピの段階発展、審査中ACT、壁割れ、鏡割れ復活を表示します。図柄は左、右の順に止まり、左右が同じ時だけ中央図柄の変動が続いてリーチへ進みます。アカスピ発展中は図柄を隠し、中央テロップで「関東1次→通過→関東2次→通過→関東最終→通過→全国決勝→優勝」を順に見せます。途中敗退や全国での優勝ならず、関東最終・全国のACTもあります。到達先が１次でも進行表示には最初から全国まで４段階を並べ、発展の結末を事前に示しません。強い保留が待機中なら液晶に先読み表示を出します。当落は変動開始時に先に決定し、その結果に合う到達段階と演出を選択します。先の審査へ通過するほど見た目の期待度が上がりますが、通過時に新たな大当たり抽選は行いません。

通常時の行事ステージは大宮祭→定期演奏会→夏ライ→芝浦祭→冬ライ→クリライ→春ライ→大宮祭の順に巡ります。液晶には現在の行事名とステージ内の回転数を表示します。大宮祭・夏ライ・芝浦祭・春ライでは、アカスピが始まらない変動に一定確率で結果発表が出ます。結果発表ではリールを隠し、ハーモニー・リズム・ステージング・表現力を各10～40点で順に発表し、合計点、30組中の順位、通過枠、通過/不通過まで見せます。順位が通過枠の曲数以内なら通過です。発表後は当落にかかわらず次のステージへ移行します。定期演奏会・クリライ・冬ライはステージ内で規定回転数を消化した後に移行します。移行中はリールを隠し、移行元と次のステージを中央のテキストで表示します。

結果発表の抽選とアカスピの抽選は別の演出ルートです。アカスピはどの通常ステージからも確率で始まり、その変動の途中で学内の結果発表から発展することはありません。内ステ通過バンド数予告は大宮祭・夏ライ・芝浦祭・春ライの結果発表で使い、12・16・20曲をその発表の通過枠にします。点数・順位・ステージ移行は演出値で、元の大当たり確率を変更しません。第1版の仮設定は結果発表率18%、規定回転12回です。これらは src/data/events.ts の行事データで変更できます。

## デバッグモード

ローカル開発中は画面右下の「開発用デバッグを開く」から入れます。URLの末尾に ?debug=1 を付けてもパネルを開けます。通常URLでは非表示です。例えば http://localhost:5173/?debug=1 です。?debug=1&fast=1 で演出短縮も有効にできます。

パネルから保留追加・満タン、次回転の強制当たり/ハズレ、RUSH突入、ST101回転目前への移動、赤/金/虹保留、壁割れ、鏡割れ復活、アカスピ4段階の到達先、審査中ACTを指定できます。たとえば「全国決勝まで」「次回転 大当たり」「設定した次回転を試す」の順に押すと全審査通過から優勝を試せます。7行事からステージを選んで移動し、結果発表型のステージでは「次回転 結果発表」、規定回転型では「規定回転 最終変動」を指定できます。設定後に「設定した次回転を試す」を押すと1入賞します。強制当落や演出は現在変動中の回転には適用されず、次に消費する保留へ適用されます。ステージ移動は通常時の変動終了後に操作してください。赤/金/虹保留は待機保留があれば先頭の色を変更し、なければ指定色の保留を1個追加します。RUSH移動は変動・BONUS中以外に操作してください。

## GitHub Pages

`.github/workflows/deploy.yml` は手動起動でテストとビルドを実行し、`dist/` をGitHub Pagesへデプロイします。公開するときはGitHubリポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定し、Actionsからこのワークフローを実行してください。デプロイが完了すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます。デバッグUIはURL末尾に `?debug=1` を付けると表示されます。

vite.config.ts の base: "./" により、リポジトリ名を含むサブパスでもビルド済みアセットを相対参照できます。画像・音声の差し替えパスもPagesでは相対パスで設定してください。
